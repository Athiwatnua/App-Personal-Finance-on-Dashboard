# Personal Finance on Dashboard

เว็บแอปสำหรับบันทึกรายรับ รายการหักประจำ และรายจ่ายส่วนบุคคล ดูสรุปและกราฟการเงินรายเดือน ข้อมูลการเงินเก็บเป็นไฟล์ JSON บนเครื่องที่รันเซิร์ฟเวอร์ ไม่ต้องมีบัญชีผู้ใช้และไม่มีการส่งข้อมูลการเงินไปบริการภายนอก หน้าเว็บโหลดฟอนต์จาก Google Fonts เมื่อเชื่อมต่ออินเทอร์เน็ต

## สถานะและเทคโนโลยี

แอปอยู่ในเวอร์ชันแรกและใช้ schema ข้อมูล version 1 ประกอบด้วยหน้าเว็บ HTML/CSS/JavaScript และเซิร์ฟเวอร์ Node.js ที่ใช้โมดูลมาตรฐาน ไม่ต้องติดตั้งแพ็กเกจ npm

เมื่อเปิดใช้งานครั้งแรก เซิร์ฟเวอร์สร้างโปรไฟล์ `My Profile 01` และไฟล์ตั้งค่าเริ่มต้นให้อัตโนมัติ โปรไฟล์เริ่มต้นยังไม่มีรายรับ รายการหัก หรือรายจ่าย

## ความสามารถ

### My Finance Record

- ตั้งชื่อและจำนวนเงินรายรับประจำ พร้อมกำหนดเดือนเริ่มมีผล การเปลี่ยนยอดจะเก็บประวัติตามเดือน เพื่อให้ดูยอดของเดือนก่อนหน้าได้
- เพิ่ม แก้ไข และลบรายการหักประจำ แต่ละรายการเก็บประวัติยอดตามเดือน และลากเพื่อจัดลำดับได้ ลำดับจะถูกบันทึกและมีแอนิเมชันระหว่างลาก
- เพิ่ม แก้ไข และลบรายจ่าย โดยระบุหมวดหมู่ จำนวนเงิน วันที่ และหมายเหตุ
- เลือกเดือนเพื่อดูรายการและสรุปเฉพาะเดือนนั้น
- แสดงรายรับรวม รายการหัก รายรับสุทธิ รายจ่าย และยอดคงเหลือ
- แสดงวันที่เป็น พ.ศ. และจัดกลุ่มหลักพันในช่องกรอกจำนวนเงิน
- แสดงหน้าต่างยืนยันก่อนลบรายการ

### My Finance Dashboard

- สรุปตัวเลขการเงินของเดือนที่เลือก
- แสดงกราฟแท่งรายจ่ายรายวันแยกสีตามหมวดหมู่ และกราฟเส้นเงินคงเหลือสะสมหลังรายจ่าย
- แสดงรายละเอียดเมื่อชี้หรือโฟกัสข้อมูลบนกราฟ พร้อมควบคุมการซูมและเลื่อนกราฟ
- แสดงสัดส่วนและยอดรายจ่ายแยกตามหมวดหมู่

### Setting

จัดการตัวเลือกที่ใช้กับรายการใหม่ได้จากเมนู **Setting**:

- เพิ่ม เปลี่ยนชื่อ ลบ และลากจัดลำดับหมวดหมู่รายจ่าย
- เพิ่ม เปลี่ยนชื่อ ลบ และลากจัดลำดับประเภทรายการหัก
- ลำดับที่จัดไว้จะใช้ในฟอร์มรายจ่ายและรายการหัก และบันทึกไว้ใน `data/settings.json`
- หมวดหมู่เริ่มต้น: ค่าอาหาร, ค่าเดินทาง, ค่าที่พัก, ค่าช้อปปิ้ง, ค่ารักษา, ค่าสาธารณูปโภค (ของใช้ประจำวัน), ค่าใช้จ่ายอื่นๆ
- ประเภทรายการหักเริ่มต้น: ประกันสังคม, บัตรเครดิต, บัตรกดเงินสด

การเปลี่ยนชื่อหรือลบตัวเลือกไม่แก้รายการย้อนหลัง รายจ่ายและรายการหักที่บันทึกไว้เก็บชื่อ ณ เวลาบันทึกเป็นข้อมูลของตัวเอง

### My Profile และ Database

- เปลี่ยนชื่อและสลับโปรไฟล์ได้ แต่ละโปรไฟล์เก็บข้อมูลในไฟล์ JSON แยกกัน
- นำเข้า Personal Finance JSON เพื่อสร้างโปรไฟล์และสลับไปยังโปรไฟล์นั้น หากพบโปรไฟล์ชื่อเดียวกันที่ยังว่าง แอปสามารถนำโปรไฟล์ว่างนั้นกลับมาใช้ได้
- ส่งออกข้อมูลของโปรไฟล์ที่เปิดอยู่เป็น JSON
- เลือกธีมสว่างหรือมืดได้
- เมนู **Database** อยู่ลำดับที่ 3 ใต้ Workspace ระหว่าง My Finance Dashboard กับ Setting ภายในมี Export data และ Import data

### Import JSON Email K+

จากเมนู **Database → Import data** เลือก **Import JSON Email K+** แอปแสดง preview และให้เลือกหมวดหมู่หนึ่งครั้งสำหรับทุกรายการในไฟล์ จากนั้นเพิ่มธุรกรรมลงในรายจ่ายของโปรไฟล์ที่เปิดอยู่

- รองรับ JSON ที่ `source` เป็น `K_PLUS`, `currency` เป็น `THB` และมี `report_date` กับ `transactions`
- จำนวนเงินที่เป็นบวกจะถูกนำเข้าเป็นรายจ่าย ยอดรายจ่ายคำนวณจาก `amount + fee`
- วันที่ทำรายการเป็นวันที่รายจ่าย ส่วนเวลา บัญชี ค่าธรรมเนียม และยอดคงเหลือเก็บไว้ในหมายเหตุ
- รายการที่ซ้ำในโปรไฟล์จะถูกข้าม โดยตรวจจากข้อมูลธุรกรรม เช่น วันที่ เวลา บัญชี จำนวนเงิน ค่าธรรมเนียม และยอดคงเหลือ
- เก็บ JSON ต้นฉบับใน `data/imports/` โดยใช้ชื่อ `import-email-kplus-DD-MM-YYYY.json` และปี พ.ศ. หากมีไฟล์ชื่อเดิมแล้วจะเติมเลขท้ายชื่อเพื่อไม่เขียนทับ

ตัวอย่างต่อไปนี้เป็นข้อมูลสมมุติทั้งหมด ใช้เพื่อแสดงรูปแบบไฟล์เท่านั้น:

```json
{
  "source": "K_PLUS",
  "account_alias": "ตัวอย่างบัญชี",
  "currency": "THB",
  "report_date": "2026-01-15",
  "transactions": [
    {
      "transaction_date": "2026-01-15",
      "transaction_time": "09:00:00",
      "account": "xxx-x-x0000-x",
      "amount": 1000.00,
      "fee": 0.00,
      "available_balance": 10000.00
    },
    {
      "transaction_date": "2026-01-15",
      "transaction_time": "10:30:00",
      "account": "xxx-x-x0000-x",
      "amount": 250.00,
      "fee": 0.00,
      "available_balance": 9750.00
    }
  ]
}
```

ข้อมูล K+ รูปแบบนี้ไม่มีชื่อร้านค้าและหมวดหมู่ แอปจึงใช้ชื่อรายการที่สร้างจากเวลา และให้ผู้ใช้เลือกหมวดหมู่เอง การนำเข้า K+ เป็นการนำเข้า JSON ที่จัดให้อยู่ในรูปแบบข้างต้น ยังไม่ใช่การอ่านอีเมลหรือ PDF โดยตรง

## เริ่มใช้งาน

ต้องติดตั้ง Node.js ก่อนใช้งาน บน Windows ให้ดับเบิลคลิก `start.bat` หรือเปิดเทอร์มินัลในโฟลเดอร์โปรเจกต์แล้วรัน:

```bash
node server.js
```

จากนั้นเปิด <http://127.0.0.1:4173> ในเบราว์เซอร์ และปิดหน้าต่างเซิร์ฟเวอร์เมื่อเลิกใช้งาน ต้องเปิดผ่านเซิร์ฟเวอร์เพื่อให้หน้าเว็บเรียก API และอ่าน/บันทึกไฟล์ JSON ได้ การเปิด `index.html` โดยตรงไม่รองรับการบันทึกข้อมูลลงไฟล์

เซิร์ฟเวอร์รับการเชื่อมต่อเฉพาะ `127.0.0.1` และใช้พอร์ต `4173` เป็นค่าเริ่มต้น หากต้องการใช้พอร์ตอื่น ให้กำหนดตัวแปร `PFD_PORT` ก่อนเริ่มเซิร์ฟเวอร์

## การจัดเก็บและสำรองข้อมูล

- `data/profiles.json` เก็บรายชื่อโปรไฟล์และรหัสโปรไฟล์ที่กำลังใช้งาน
- `data/finance.json` เก็บข้อมูลของโปรไฟล์เริ่มต้น
- โปรไฟล์อื่นมีไฟล์ JSON แยกใน `data/` เช่น `finance-<รหัส>.json`
- `data/settings.json` เก็บหมวดหมู่และตัวเลือกรายการหักที่ใช้ร่วมกันทุกโปรไฟล์
- `data/imports/` เก็บไฟล์ JSON ต้นฉบับจาก Email K+
- `localStorage` ในเบราว์เซอร์เก็บแคชสำรองและค่าธีม ส่วนไฟล์ JSON ใน `data/` เป็นแหล่งข้อมูลหลัก

ควรสำรองโฟลเดอร์ `data/` เป็นระยะ การส่งออกโปรไฟล์จะไม่รวม `settings.json` หรือไฟล์ต้นฉบับใน `data/imports/` หากย้ายโปรเจกต์และต้องการเก็บการตั้งค่ากับไฟล์นำเข้าด้วย ให้คัดลอกโฟลเดอร์ `data/` ทั้งหมด

## นำเข้าและส่งออก Personal Finance JSON

เมนู **Database → Export data** ส่งออกข้อมูลล่าสุดของโปรไฟล์ที่เลือกเป็นไฟล์ชื่อประมาณ `personal-finance-<ชื่อโปรไฟล์>-<YYYY-MM-DD>.json` ซึ่งมีรายรับปัจจุบัน ประวัติรายรับ รายการหักพร้อมประวัติ และรายจ่ายทั้งหมด

เมนู **Database → Import data → Personal Finance JSON** รับไฟล์ schema version 1 ที่ส่งออกจากแอป การนำเข้าจะสร้างหรือใช้โปรไฟล์ว่างที่มีชื่อเดียวกัน และไม่เขียนทับโปรไฟล์เดิมที่มีข้อมูลแล้ว

ตัวอย่างโครงสร้าง:

ตัวอย่างนี้ใช้ข้อมูลสมมุติทั้งหมด ยอด `1000` เป็นตัวเลขสาธิต ไม่ใช่ข้อมูลบัญชีจริง

```json
{
  "version": 1,
  "profile": { "name": "บัญชีส่วนตัว" },
  "income": { "name": "รายรับหลัก", "amount": 0 },
  "incomeHistory": [],
  "deductions": [
    {
      "id": "deduction-1",
      "name": "ตัวอย่างรายการหัก",
      "amount": 0,
      "history": [
        { "month": "2026-01", "amount": 0 }
      ]
    }
  ],
  "expenses": [
    {
      "id": "expense-1",
      "title": "ค่าเดินทาง",
      "amount": 1000,
      "category": "ค่าเดินทาง",
      "date": "2026-01-15",
      "note": ""
    }
  ]
}
```

เดือนใน `incomeHistory` และ `deductions[].history` ใช้รูปแบบ `YYYY-MM` และเรียงตามเดือนที่เริ่มมีผล แอปใช้ยอดล่าสุดที่เริ่มมีผลตั้งแต่เดือนที่เลือกหรือก่อนหน้า `income` และ `deductions[].amount` เป็นยอดตั้งต้นก่อนประวัติที่ระบุ

## โครงสร้างไฟล์หลัก

```text
├── app.js             # การทำงานหน้าเว็บ การคำนวณ และเรียก API
├── index.html         # โครงสร้างหน้าและฟอร์ม
├── server.js          # เว็บเซิร์ฟเวอร์และ API สำหรับข้อมูลในเครื่อง
├── styles.css         # รูปแบบหน้าจอหลักและ responsive layout
├── styles-theme.css   # ธีม แอนิเมชัน ส่วนประกอบเพิ่มเติม และกราฟ
├── start.bat          # เริ่มเซิร์ฟเวอร์บน Windows
└── data/              # สร้างโดยเซิร์ฟเวอร์เมื่อเริ่มใช้งาน
    ├── profiles.json
    ├── finance.json
    ├── settings.json
    └── imports/       # ไฟล์ต้นฉบับจาก Email K+
```

## ข้อจำกัดปัจจุบัน

- โปรไฟล์ใหม่สร้างได้จากการนำเข้า Personal Finance JSON ยังไม่มีหน้าสร้างหรือลบโปรไฟล์โดยตรง
- K+ importer รองรับ JSON ตาม schema ที่ระบุเท่านั้น ยังไม่อ่านอีเมลหรือ PDF โดยตรง และใช้หมวดหมู่เดียวกับทุกรายการในไฟล์
- รายจ่ายและการตั้งค่าจัดเก็บในเครื่องที่รันเซิร์ฟเวอร์ ยังไม่มีบัญชีผู้ใช้หรือระบบซิงก์ข้ามอุปกรณ์
- หากเซิร์ฟเวอร์ไม่พร้อม แอปอาจแสดงข้อมูลจากแคชได้ แต่การแก้ไขจะไม่ถูกบันทึกลงไฟล์จนกว่าเซิร์ฟเวอร์จะกลับมาทำงาน
