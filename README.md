# Personal Finance on Dashboard

เว็บแอปสำหรับบันทึกรายรับและรายจ่ายส่วนบุคคล ติดตามภาพรวมการเงินรายเดือน และแยกข้อมูลตามโปรไฟล์ ข้อมูลหลักเก็บเป็นไฟล์ JSON ในเครื่อง ไม่ต้องสมัครบัญชี และไม่มีการส่งข้อมูลไปยังบริการภายนอก

## สถานะของโปรเจกต์

โปรเจกต์อยู่ในเวอร์ชันแรก (schema ข้อมูล version 1) ประกอบด้วยหน้าเว็บแบบ static และเซิร์ฟเวอร์ Node.js ที่ใช้โมดูลมาตรฐาน ไม่ต้องติดตั้งแพ็กเกจจาก npm ข้อมูลเริ่มต้นอยู่ในโปรไฟล์ `My Profile 01` โดยยังไม่มีรายรับ รายการหัก หรือรายจ่าย

## ความสามารถ

### My Finance Record

- ตั้งชื่อและจำนวนเงินของรายรับประจำ พร้อมระบุเดือนที่ยอดใหม่เริ่มมีผล ประวัติรายรับของเดือนก่อนหน้าจะยังคงเดิม
- เพิ่ม แก้ไข และลบรายการหักประจำ แต่ละรายการมีประวัติยอดที่เริ่มมีผลในแต่ละเดือน
- เลือกประเภทรายการหักจากรายการที่ตั้งค่าไว้ โดยค่าเริ่มต้นมี ประกันสังคม, บัตรเครดิต และบัตรกดเงินสด
- เพิ่ม แก้ไข และลบรายจ่าย โดยระบุหมวดหมู่ จำนวนเงิน วันที่ และหมายเหตุ (ไม่บังคับ)
- เลือกเดือนเพื่อดูรายการและสรุปการเงินของเดือนนั้น
- แสดงรายรับรวม รายการหัก รายรับสุทธิ รายจ่าย และยอดคงเหลือ
- จัดลำดับรายการหักด้วยการลากและวาง

ตั้งค่าหมวดหมู่รายจ่ายและตัวเลือกรายการหักได้จากเมนู **Setting** การเพิ่ม แก้ไข หรือลบตัวเลือกมีผลกับตัวเลือกที่ใช้บันทึกใหม่เท่านั้น รายการที่บันทึกแล้วจะเก็บชื่อหมวดหมู่หรือชื่อรายการหักเดิมไว้

### My Finance Dashboard

- แสดงตัวเลขสรุปของเดือนที่เลือก
- แสดงกราฟแท่งรายจ่ายรายวัน แยกสีตามหมวดหมู่ และกราฟเส้นเงินคงเหลือสะสมหลังหักรายจ่ายในแต่ละวัน
- แสดงรายละเอียดเมื่อชี้หรือโฟกัสจุดบนกราฟ พร้อมควบคุมการซูมและเลื่อนดูกราฟ
- แสดงสัดส่วนและยอดรายจ่ายแยกตามหมวดหมู่

### My Profile และ Database

- เปลี่ยนชื่อและสลับโปรไฟล์ได้ แต่ละโปรไฟล์มีไฟล์ข้อมูลแยกกัน
- นำเข้าไฟล์ JSON เพื่อสร้างโปรไฟล์ใหม่และสลับไปยังโปรไฟล์นั้นทันที หากมีโปรไฟล์ชื่อเดียวกันและยังไม่มีข้อมูล ระบบอาจนำโปรไฟล์ว่างนั้นกลับมาใช้
- ส่งออกข้อมูลของโปรไฟล์ที่เลือกเป็นไฟล์ JSON
- เลือกธีมสว่างหรือมืดได้

เมนู **Database** อยู่ภายใต้หัวข้อ Workspace ในแถบด้านข้าง

## เริ่มใช้งาน

ต้องติดตั้ง Node.js ก่อนใช้งาน

บน Windows ให้ดับเบิลคลิก `start.bat` หรือเปิดเทอร์มินัลในโฟลเดอร์โปรเจกต์แล้วรัน:

```bash
node server.js
```

จากนั้นเปิด <http://127.0.0.1:4173> ในเบราว์เซอร์ ปิดหน้าต่างเซิร์ฟเวอร์เมื่อเลิกใช้งาน

ต้องเปิดแอปผ่านเซิร์ฟเวอร์นี้เพื่อให้หน้าเว็บอ่านและเขียนไฟล์ข้อมูลได้ การเปิด `index.html` โดยตรงจะไม่สามารถบันทึกข้อมูลลง JSON ผ่าน API ได้

เซิร์ฟเวอร์รับการเชื่อมต่อเฉพาะ `127.0.0.1` และใช้พอร์ต `4173` เป็นค่าเริ่มต้น หากต้องการใช้พอร์ตอื่น สามารถกำหนดตัวแปร `PFD_PORT` ก่อนเริ่มเซิร์ฟเวอร์ได้

## การจัดเก็บข้อมูล

- `data/profiles.json` เก็บรายชื่อโปรไฟล์และรหัสโปรไฟล์ที่ใช้งานอยู่
- `data/finance.json` เก็บข้อมูลของโปรไฟล์เริ่มต้น
- โปรไฟล์ที่นำเข้าใหม่จะมีไฟล์ข้อมูล JSON ของตัวเองในโฟลเดอร์ `data/`
- `data/settings.json` เก็บรายการหมวดหมู่รายจ่ายและตัวเลือกรายการหัก ซึ่งใช้ร่วมกันทุกโปรไฟล์และสร้างค่าเริ่มต้นให้อัตโนมัติเมื่อเปิดแอปครั้งแรก
- `data/imports/` เก็บไฟล์ JSON ต้นฉบับที่นำเข้าจาก Email K+ โดยแยกไฟล์ตามวันที่นำเข้า เช่น `import-email-kplus-24-11-2569.json`
- เบราว์เซอร์มีแคชสำรองของข้อมูลและค่าธีมผ่าน `localStorage` แต่ไฟล์ JSON ในเครื่องเป็นแหล่งข้อมูลหลัก

ข้อมูลหมวดหมู่และรายการหักที่บันทึกในแต่ละโปรไฟล์เก็บชื่อ ณ เวลาบันทึกไว้เป็นข้อมูลย้อนหลัง การเปลี่ยนหรือลบตัวเลือกใน Setting จึงไม่แก้รายการเดิม การส่งออก/นำเข้าข้อมูลโปรไฟล์ยังคงเก็บชื่อเดิมและไม่เปลี่ยน `settings.json`; หากย้ายทั้งแอปไปเครื่องอื่น ให้คัดลอกโฟลเดอร์ `data/` เพื่อย้ายตัวเลือกที่ตั้งค่าไว้ด้วย

ควรสำรองโฟลเดอร์ `data/` หรือส่งออกข้อมูลเป็นระยะ หากย้ายโปรเจกต์ไปเครื่องอื่น ให้นำข้อมูลที่ส่งออกไปนำเข้าในโปรเจกต์ปลายทาง หรือคัดลอกโฟลเดอร์ `data/` ไปด้วย

## นำเข้าและส่งออกข้อมูล

เปิดเมนู **Database** ในแถบด้านซ้าย แล้วเลือก **Export data** หรือ **Import data**

เมื่อเลือก Import data สามารถเลือก **Personal Finance JSON** สำหรับไฟล์ที่ส่งออกจากแอป หรือ **Import JSON Email K+** สำหรับไฟล์รายงานที่มี `source: "K_PLUS"`, สกุลเงิน THB และรายการ `transactions` แอปจะแสดงตัวอย่างและให้เลือกหมวดหมู่ก่อนเพิ่มรายการ ธุรกรรมจะบันทึกลงรายจ่ายของโปรไฟล์ที่เปิดอยู่ โดยใช้จำนวนเงินบวกและค่าธรรมเนียมเป็นยอดรายจ่าย วันเวลาและข้อมูลบัญชีจะเก็บในหมายเหตุ และเก็บไฟล์ต้นฉบับใน `data/imports/` รายการเดิมที่นำเข้าซ้ำจะถูกข้าม

ลำดับที่ลากจัดใน Setting จะถูกบันทึกใน `data/settings.json` และใช้เรียงตัวเลือกในฟอร์มรายจ่าย/รายการหักด้วย

การส่งออกจะอ่านข้อมูลล่าสุดของโปรไฟล์ที่เลือกและสร้างไฟล์ชื่อประมาณ `personal-finance-<ชื่อโปรไฟล์>-<YYYY-MM-DD>.json` โดยข้อมูลประกอบด้วยรายรับปัจจุบัน ประวัติรายรับ รายการหักพร้อมประวัติ และรายจ่ายทั้งหมด

การนำเข้าต้องเป็น JSON schema version 1 แอปจะตรวจสอบข้อมูลและให้เซิร์ฟเวอร์สร้างโปรไฟล์จากไฟล์นั้น การนำเข้าไม่ได้เขียนทับโปรไฟล์ที่มีข้อมูลอยู่

ตัวอย่างโครงสร้างไฟล์:

```json
{
  "version": 1,
  "profile": { "name": "บัญชีส่วนตัว" },
  "income": { "name": "เงินเดือน", "amount": 30000 },
  "incomeHistory": [
    { "month": "2026-12", "name": "เงินเดือน", "amount": 32000 }
  ],
  "deductions": [
    {
      "id": "deduction-1",
      "name": "ประกันสังคม",
      "amount": 0,
      "history": [
        { "month": "2026-11", "amount": 750 }
      ]
    }
  ],
  "expenses": [
    {
      "id": "expense-1",
      "title": "ค่าเดินทาง",
      "amount": 120,
      "category": "ค่าเดินทาง",
      "date": "2026-11-17",
      "note": ""
    }
  ]
}
```

`incomeHistory` และ `deductions[].history` เรียงตามเดือนที่เริ่มมีผล: เดือนที่เลือกจะใช้รายการล่าสุดที่มีผลตั้งแต่เดือนนั้นหรือก่อนหน้า ส่วน `income` และ `deductions[].amount` เป็นยอดตั้งต้นก่อนประวัติที่บันทึกไว้

## โครงสร้างไฟล์หลัก

```text
├── app.js             # การทำงานหน้าเว็บ การคำนวณ และเรียก API
├── index.html         # โครงสร้างหน้าและฟอร์ม
├── server.js          # เว็บเซิร์ฟเวอร์และ API สำหรับข้อมูลในเครื่อง
├── styles.css         # รูปแบบหน้าจอหลักและ responsive layout
├── styles-theme.css   # ธีม ส่วนประกอบเพิ่มเติม และการแสดงผลกราฟ
├── start.bat          # เริ่มเซิร์ฟเวอร์บน Windows
└── data/
    ├── profiles.json  # รายชื่อและโปรไฟล์ที่ใช้งานอยู่
    └── finance.json   # ข้อมูลโปรไฟล์เริ่มต้น
```

## ข้อจำกัดปัจจุบัน

- โปรไฟล์ใหม่เพิ่มผ่านการนำเข้าข้อมูล ส่วนการสร้างและลบโปรไฟล์โดยตรงยังไม่มีในหน้าจอ
- หมวดหมู่รายจ่ายเป็นรายการคงที่ในฟอร์ม ยังเพิ่มหรือจัดการหมวดหมู่เองไม่ได้
- ข้อมูลถูกเก็บในเครื่องที่รันเซิร์ฟเวอร์ แอปนี้ยังไม่มีระบบบัญชีผู้ใช้หรือซิงก์ข้ามอุปกรณ์
- การเปิดหน้าเว็บโดยไม่เชื่อมต่อเซิร์ฟเวอร์จะแสดงแคชในเบราว์เซอร์ได้ หากมี แต่การแก้ไขจะไม่ถูกบันทึกลงไฟล์ JSON จนกว่าเซิร์ฟเวอร์จะพร้อมใช้งาน
